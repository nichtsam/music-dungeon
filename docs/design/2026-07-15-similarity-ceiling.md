# 相似度上限與同名去重 — 探索多樣性

2026-07-15 · 狀態：已定案，已實作

## 問題

真實 API 上線後，門後大量「幾乎同一首」的歌（remaster、重複上傳），探險變成連續聽重複曲。原本候選 filter 只有下限 `DOOR_THRESHOLD = 0.72`。

## 決策

1. **相似度上限 `DOOR_CEILING = 0.95`**：分數超過視為同曲複製品，不開門也不開 portal。
2. **正規化標題去重**（小寫、去 `.mp3` 後綴、trim）：與當前房間同名、或候選彼此同名者只留分數最高的一個。Jamendo 目錄常見同曲不同 id 重複上傳，分數未必碰頂，光靠上限擋不住。

兩者都作用在 `generateExits` 的 `eligible` filter（`dungeon.ts`），門與 portal 規則一致。入口 fallback（保證至少一條路）不套用 — 有路優先於多樣性。

## 否決選項

- **只設上限不去重** — 重複上傳的相似分數常落在 0.8x，上限抓不到。
- **上限 0.90** — 怕誤殺正當的高相似好歌；先保守，實測再收緊。
- **多樣性抽樣演算法**（依分數/風格分佈挑選）— 複雜度不符 demo 規模；硬上限 + 去重先觀察效果。

## 與核心原則的關係

不影響聆聽/dwell 機制（[2026-07-12-attunement-stats.md](2026-07-12-attunement-stats.md)）— 只改變「哪些歌成為鄰居」，不減少聽歌需求。

## 調參記錄

- 2026-07-15：初值 0.95（Sam 拍板）。實測分佈回報後回填。

## 副作用（預期內）

Mock fixture 的 `(Reprise)`／`(Night Mix)` 變體與原曲相似度約 0.96，會被上限剪掉 — 正是此機制的目標行為。
