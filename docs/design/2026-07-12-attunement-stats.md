# Attunement 能力系統 v1 — 設計與理念

2026-07-12 · 狀態:已定案,v1 實作中

## 核心理念(硬性原則)

**遊戲鼓勵玩家多聽、多探索音樂。** 一切成長效果只能放大探索的價值(跑更快、跑更久、看得更多),**不得縮短聆聽/attune 所需時間**。縮短聆聽等於獎勵跳過音樂,直接違反遊戲主旨。

## Attunement 定義

- 本義:**聽完整一首歌**即 attune 該 track,獲得能力值。
- 現況代理:app 尚無實際音樂播放,暫以**房間停留時間**(`dwell ≥ DWELL_TARGET`,30 秒)代替。
- 未來:接上真實播放(M4 之後)改為以整首播放完成度計算,`DWELL_TARGET` 換成 track 實際長度。
- attune **自動發生**,無需操作;attunements view(原 nest view,2026-07-12 改名對齊機制)是成長的視覺化/閱讀介面(能力樹),地圖第 4 頁籤 STATS 顯示能力值明細與每首歌的貢獻。

## 能力值(v1:兩維)

| 能力值 | 效果 |
|---|---|
| 敏捷 Agility | sprint 速度倍率 `2.0 + agility × 0.1` |
| 耐力 Stamina | sprint 最大續航 `1.5 + stamina × 0.5` 秒 |

基礎續航刻意短(1.5 秒),讓每首慢歌的成長都有感。耐力條:sprint 且移動時消耗,放開回復(全滿約 8 秒),耗盡後回復至 15% 才可再 sprint。

> 調參記錄 2026-07-12:初版基礎 3 秒 / +0.8 秒 / 5 秒回滿,試玩後太慷慨,全數下修。

### BPM 分流

每 attune 一首歌固定獲得 1 點總量,依 BPM 比例切分 — 快歌餵敏捷、慢歌餵耐力:

```
agilityShare(bpm) = bpm == null ? 0.5 : clamp((bpm - 60) / 120, 0, 1)
```

| BPM | 敏捷 | 耐力 |
|---|---|---|
| 180+ | +1.0 | 0 |
| 120 | +0.5 | +0.5 |
| 60- | 0 | +1.0 |
| null(偵測不到) | +0.5 | +0.5 |

### 實作原則:純推導

能力值不持久化 — 從既有 `dwell` + `tracks` 推導(`dwell[cellKey] ≥ DWELL_TARGET` 即 attuned)。零遷移、舊存檔直接生效、狀態不會不同步。

## 已否決方案(附理由)

- **共鳴 Resonance(加速 attune)**:縮短 DWELL_TARGET = 獎勵跳過音樂,違反核心理念。任何未來設計都不得重提此類效果。
- **感知揭露 nest 鎖定節點資訊**:nest view 是抽象相似度空間,與地城座標無掛勾,提前看到鎖定節點的 mood/BPM 也無法導航,情報無用。灰色鎖定節點維持「還有未探索」的簡單提示即可。
- **主動點擊 attune**:改為自動,降低操作成本;nest view 專注於閱讀成長。
- **mood 向量分流**:改用 BPM 分流,快慢直覺好懂;mood 留給未來維度(如戰鬥屬性)。

## 未來擴充方向(待地基驗證後另開設計)
